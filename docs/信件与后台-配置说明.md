# 「寄一封信」与信件后台 — 现状、配置与测试

> 结论先说：寄信**不是**存 localStorage，而是真的 `POST /api/letters` 写进 **Cloudflare D1**。
> 之所以"点了没反应"，是两个原因叠加：**首页/顶栏原本没有入口**，以及**后端不可用时错误提示被 CSS 隐藏**（已修）。

## 一、现在的入口在哪

| 位置 | 元素 | 说明 |
|---|---|---|
| 顶栏（全站可见） | `#navLetterBtn`「写信」 | 2026-11 新增，任何页面都能点 |
| 作品阅读页底部 | `.open-letter-modal-btn` | 《xxx》页面下方「寄一封信」区块 |
| 关于页 | `.open-letter-modal-btn` | 关于页底部入口 |

点开后是同一个弹窗（`#letterModal`），正文支持 4000 字，可选填称呼与邮箱，带隐藏蜜罐 `hp_check` 防机器人。

## 二、发送链路（已核对源码）

```
点击「寄出信件」
  → 前端校验（正文非空、邮箱格式）
  → POST /api/letters  { sender_name, sender_email, content, work_slug, hp_check }
  → Cloudflare Pages Functions: functions/api/letters.js
  → 校验 D1 绑定 env.DB → 自动建表（幂等）→ INSERT INTO letters
  → 返回 201 { success: true, message }  → 弹窗显示"信件已静静送达井底"
  → 失败：显示具体原因（HTTP 状态码 + 后端 message）
```

**本地存储用得很少**，只有三处，都与信件内容无关：

| key | 存储位置 | 用途 |
|---|---|---|
| `crow_well_theme` | localStorage | 深浅色主题 |
| `crow_well_reader_font_level` | localStorage | 阅读页字号档位 |
| `crow_well_admin_secret` | **sessionStorage** | 后台登录密码（关标签页即失效） |

也就是说：**信件本身从不落在浏览器里**。如果后端没配好，信是发不出去的，前端也不会偷偷存一份。

## 三、Cloudflare 一次性配置（必做，否则 503）

### 1) 建 D1 数据库
Cloudflare Dashboard → **Storage & Databases → D1** → Create database → 名字随意（如 `wcrow`）。

### 2) 绑定到 Pages 项目
Pages 项目 → **Settings → Functions → D1 database bindings** → Add：
- Variable name：**`DB`**（必须叫 DB，代码里就是 `env.DB`）
- D1 database：选刚建的那个
- 环境：Production（Preview 也建议加一份）

### 3) 设置管理员密码
Pages 项目 → **Settings → Environment variables** → Add：
- Name：**`ADMIN_SECRET`**
- Value：一个足够长的随机串（例如 `openssl rand -hex 24` 生成）
- 勾选加密（Secret）

> 这两个都加好后，**必须重新部署一次**（Deployments → Retry deployment），环境变量才会注入到 Functions。

### 4) 表结构
`functions/api/letters.js` 第一次请求时会自动执行 `CREATE TABLE IF NOT EXISTS`，一般不用手动建。
若你想手动建（或数据库权限受限）：

```sql
CREATE TABLE IF NOT EXISTS letters (
  id TEXT PRIMARY KEY,
  sender_name TEXT,
  sender_email TEXT,
  content TEXT NOT NULL,
  work_slug TEXT,
  created_at INTEGER NOT NULL,
  is_read INTEGER DEFAULT 0
);
```

## 四、后台怎么用

访问 `https://<你的域名>/#/admin/letters`：

1. 输入与 `ADMIN_SECRET` 一致的密码 → 进入信箱
2. 列表按时间倒序（最多 100 条），显示称呼 / 来源作品 slug / 时间 / 正文
3. 可「标为已读」「删除」
4. 密码只存在 sessionStorage，**刷新还在、关掉标签页就失效**；「锁定退出」可立即清除

页面 `admin/` 目录是 Decap CMS 写稿台（另一套东西），与本信后台无关。

## 五、本地怎么看信件（不依赖线上）

前端没有本地存储，所以**本地查看＝把后端也跑起来**：

```bash
cd wcrow
npx wrangler d1 create wcrow                 # 首次
npx wrangler d1 execute wcrow --local --command "SELECT 1"   # 初始化本地库
npx wrangler pages dev . --d1 DB=wcrow --binding ADMIN_SECRET=dev-secret
# 打开 http://127.0.0.1:8788/#/admin/letters ，密码填 dev-secret
```

`--local` 模式下数据存在 `.wrangler/state/`，可用 SQL 直接查：

```bash
npx wrangler d1 execute wcrow --local --command "SELECT datetime(created_at/1000,'unixepoch') AS t, sender_name, content FROM letters ORDER BY created_at DESC"
```

## 六、完整测试步骤（你在线上亲自发一封）

### 1. 发信（浏览器）
1. 打开首页 → 顶栏点 **写信**
2. 正文写：`测试信件 · 2026-11-03`
3. 称呼填 `测试读者`，邮箱留空
4. 点「寄出信件 𓅂」
   - ✅ 应看到绿色提示：**信件已静静送达井底。**（1.8 秒后弹窗自动关闭）
   - ❌ 若看到红色提示，按第七节排障

### 2. 发信（命令行，排除浏览器因素）
```bash
curl -i -X POST https://<你的域名>/api/letters \
  -H "Content-Type: application/json" \
  -d '{"sender_name":"命令行测试","content":"curl 测试信件","work_slug":"","hp_check":""}'
```
预期：`HTTP/2 201` + `{"success":true,"message":"信件已静静送达井底。","id":"let_..."}`

### 3. 后台确认
1. 打开 `https://<你的域名>/#/admin/letters`
2. 输入 `ADMIN_SECRET` → 进入信箱
3. 应看到刚发的两封（命令行那封 + 浏览器那封），时间倒序
4. 点「标为已读」，刷新后状态保持；点「删除」可移除

### 4. 直接查数据库（最终验证，排除前端显示问题）
```bash
npx wrangler d1 execute wcrow --remote --command \
  "SELECT id, sender_name, content, datetime(created_at/1000,'unixepoch') FROM letters ORDER BY created_at DESC LIMIT 5"
```

## 七、排障对照表

| 现象 | 真实原因 | 处理 |
|---|---|---|
| 提示 `HTTP 501 / 503`，文案含「后端接口暂不可用」/「DATABASE_UNAVAILABLE」 | 静态托管（无 Functions）或 D1 未绑定 `DB` | 按第三节第 2 步绑定 DB，并重新部署 |
| 提示「环境变量 ADMIN_SECRET 尚未设置」 | 没加环境变量 | 第三节第 3 步，加完重新部署 |
| 提示「鉴权未通过：密码错误」 | 后台输入的密码与 `ADMIN_SECRET` 不一致 | 用同一个值登录（注意首尾空格） |
| 提示「网络异常」 | 域名解析/CDN 中断 | 网络恢复重试 |
| 提示「请先写下想说的话」但文本框明明有字 | 只有空白字符（空格/换行） | 写实质内容 |
| 点了完全没反应（旧版） | 状态条被 `display:none` 隐藏 + 顶栏无入口 | 已修复：状态条现在必定显示，顶栏新增「写信」 |

## 八、安全与后续建议

- **必须**：`ADMIN_SECRET` 用长随机串，且只放在 Pages 环境变量（不要写进仓库）。
- 现状 CORS 为 `*`，任何人都能调 `POST /api/letters`（这是有意的：读者留言需要公开写入口）。
  写接口已有正文长度、邮箱格式、蜜罐三重限制；若被刷，可在 `functions/api/letters.js` 里加
  频率限制（如按 IP + 时间窗）或接入 Turnstile。
- 读/改/删接口必须带 `Authorization: Bearer <ADMIN_SECRET>`，未配置密钥时直接返回 500，不会裸奔。
- 信件正文最长 5000 字（后端）/ 4000 字（前端输入框），超过会被后端拒绝。
